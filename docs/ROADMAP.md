# Product Roadmap

This records current direction, not commitments or dates. Raw ideas and small fixes remain in the owner's lightweight personal Notes backlog rather than being duplicated here.

## Current stage — Build it well for myself

Development is driven by real day-to-day use, friction noticed while using the product, missing useful information or insight, financial correctness, valuable features, necessary technical foundations, and practical AI/software-development learning.

Before the next major feature, the current focus is to improve durable project context; clarify planning versus implementation, review, and research; improve use of ChatGPT Chat, Work, and Codex; use independent AI review; and improve model/reasoning selection.

Likely near-term areas, without commitment:

- Distinguish investment-value change from money entering or leaving the portfolio
- Small UX improvements discovered through use
- Clearer investment-versus-cash presentation
- Data Check workflow improvements
- Broader account and asset support
- Refine pension and fixed-rate deposit workflows from real use
- Better portfolio sorting and classification behavior

## Next stage — Friends and family

The goal is to discover assumptions that work only because the developer is currently the user. Likely needs include broader Israeli, US, and international security/fund support; stronger automatic geography/exposure classification; broader geography/sector options; better onboarding and explanations; support for different portfolio structures; clearer financial terminology; and sufficient backup/data-safety confidence for other users.

Real feedback should outweigh speculative feature planning.

Deposit extensions to evaluate at this stage include variable-rate deposits, Prime-linked deposits, and CPI-linked deposits. These require explicit product semantics and reliable reference-rate/index handling before implementation.

## Later stage — Public/open beta

This stage should begin only after the product works for users without direct access to the developer. It would require deliberate review of onboarding, errors, data safety/recovery, privacy/security, deployment reliability, user-specific data separation, market-data reliability, varied portfolio compatibility, financial/product explanations, and support/debugging workflows.

An open beta would not automatically mean a commercial business.

## Potential future directions

These are preserved possibilities, not commitments:

- Richer performance/history
- Dividends
- Target allocation/rebalancing
- Additional pension detail only where real user needs justify it
- Additional non-market wealth products and account types
- Liabilities/debt
- Expenses/budgeting
- Bank/broker integrations
- ChatGPT integration
- Forecasting/AI-assisted insights

## Deferred / blocked

- Automatic scheduled snapshots remain blocked until there is a verified scheduling/cron deployment path.
- Broad bank/broker integrations are deferred because of complexity, security, reliability, provider, and maintenance concerns.
- Tax and full accounting remain outside current scope.
- AI financial advice is not currently a priority.

## Prioritization criteria

1. Value to actual users
2. Observed friction or unmet need
3. Financial correctness and trust
4. Learning value
5. Implementation and maintenance complexity
6. Whether the work helps reach the next maturity stage
